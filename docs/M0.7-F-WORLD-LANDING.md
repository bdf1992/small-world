# M0.7-F — World Landing + Backward Trace

Status: **machine-gated slice in progress; owner acceptance pending**

M0.7-F closes the forward/backward loop between authored meaning and a realized world object.

M0.7-A through E already prove:

```text
Card / Pack authored truth
    ↓
shared tuple graph
    ↓
bounded Resolution
    ↓
World Instance
```

F adds the inverse read:

```text
World Instance
    ↓ inspect backward
Lifecycle + composition custody
    ↓
Card / Template + Pack Slot + Requirement + Situation + Region
```

## Quality lines

> **A realized object should be able to explain where it came from without the browser reconstructing its provenance.**

> **Lifecycle provenance and composition provenance are related, but they are not the same edge.**

> **A stopped Virtual is not a landed Instance.**

## Application-owned landing projection

`src/app/world-lineage.js` creates a `WorldLanding` projection from the resolved World projection plus the active authoring/template registry.

The projection is keyed by the actual World object key:

```text
landing.byObject["artifact:<instance-id>"]
```

Each trace contains:

- landed Instance identity;
- lifecycle chain;
- source Card or catalog Template;
- authored-vs-catalog classification;
- parent Pack;
- Pack Slot/role;
- Slot Requirement;
- parent Situation;
- containing Region;
- an explicit backward custody sequence.

The same information is also projected as typed tuples in `views.landing`.

## Two provenance lanes

### Lifecycle lane

The ordinary realization lifecycle remains:

```text
Definition
  → Template
  → Reference
  → Virtual
  → Instance
```

The landing graph exposes the inverse evidence direction with `derived-from` tuples.

### Composition lane

A Pack member also has compositional custody:

```text
Card / Template
    ↓ bound-to
Pack Slot
    ↓ requires
Requirement
    ↓ composed-by
Pack
    ↓ realized as
Situation
    ↓ contained by
Region
```

A landed member satisfies the Requirement of the Slot through which it entered the Situation.

F keeps these lanes explicit instead of pretending `Pack Slot` is a lifecycle stage.

## Authored vs catalog content

F must not claim all realized Templates were authored in the M0.7 workbench.

Example on seed `93208` after authoring Ice Dragon:

```text
Ice Dragon guardian
  source = persona.ice-dragon
  source kind = authored Card
  Pack = pack.spire
  Pack kind = authored Pack

Sword treasure
  source = item.sword
  source kind = catalog Template
  Pack = pack.spire
  Pack kind = authored Pack
```

This distinction matters because a Pack can be authored while selecting a canonical catalog Template.

## Canonical F proof

```text
Dragon Card
    ↓ clone/edit
Ice Dragon Card

Mountains / Spire / Ice Dragon Instance
    ↓ landing trace
persona.ice-dragon
```

The trace must survive E's Authoring Document export/import path because persistence recreates authored truth, not realized objects.

## Budget boundary

With full budget the canonical horizontal world contains six landed Pack-member Artifacts and therefore six traceable landing entries.

With:

```text
maxHops      = 4
maxSlots     = 6
maxInstances = 0
```

Resolution stops after Virtual creation.

The required F invariant is:

```text
World status = unresolved
landing state = unresolved
landing.traceable = []
landing.byObject = {}
```

No `Virtual` may be presented as a landed `Instance` merely because it already carries rich possibility data.

## Projection contract

The Authoring & Resolution wrapper advances to projection version `6`.

New surfaces:

```text
projection.landing
projection.views.landing
projection.trees.landing
```

`projection.landing` is the compact application read:

- state;
- traceable World object keys;
- `byObject` trace index.

`views.landing` is the typed tuple graph.

`trees.landing` is a bounded rooted projection of that graph.

## Browser behavior

The browser remains a projection consumer.

In World mode it:

- shows landed Situation members beneath each Situation;
- opens the application-provided backward custody trace in the inspector;
- shows lifecycle separately from Pack composition;
- can return to an authored source Card;
- can open the authored Pack;
- can open the Resolution graph.

The browser does not derive Card/Pack/Requirement provenance from ids or DOM structure.

`web/world-lineage.js` obtains the current application projection and renders only the supplied trace.

## Verification targets

`npm run verify:lineage` must prove:

1. projection version 6 exposes `WorldLanding`;
2. the resolved canonical horizontal world exposes six landed Artifact traces;
3. authored Ice Dragon traces back to `persona.ice-dragon` as an authored Card;
4. the same Ice Dragon traces through `pack.spire.slot.guardian`;
5. guardian Requirement is `Artifact/Persona × 1`;
6. trace lands in Spire / Mountains;
7. lifecycle is Definition → Template → Reference → Virtual → Instance;
8. landing graph contains explicit Card, Slot, Requirement, Situation and Region custody tuples;
9. canonical Sword remains a catalog Template while its Spire Pack remains authored;
10. E Authoring Document import recreates the same Ice Dragon source trace;
11. `maxInstances = 0` exposes no landed traces;
12. HTTP application projection exposes the same trace;
13. browser lineage assets are served and syntax-valid;
14. reset-budget restores the landed trace without changing authored truth;
15. the entire inherited M0.5 / M0.6 / M0.7-A..E suite remains green.

## Deliberately deferred

F does not add:

- editing from the World surface itself;
- arbitrary graph history/time travel;
- runtime save-state persistence;
- provenance across multiple Authoring Documents;
- repository/source-control locations for Cards or Packs;
- a generic causal debugger;
- final visual consolidation.

M0.7-G remains responsible for the shared visual language across world, instruments, authoring, resolution, and provenance.
