# M0.7-D — Resolution Frontier

Status: **machine-verified slice; owner acceptance pending**

This slice makes bounded resolution visible and controllable without moving runtime budget into Card or Pack authoring data.

## The separation

Small World now treats two kinds of change as different state axes:

```text
Authoring axis
Card / Pack mutation
        ↓
authoring revision

Resolution axis
Hops / Slots / Instances
        ↓
resolution revision
```

Changing compute budget does **not** edit a Card, Pack, Requirement, or Rule.

Changing authored content does **not** masquerade as a runtime-budget operation.

That distinction is visible in the application projection as:

```text
revision
resolutionRevision
```

## Budget

The bounded resolver already owns three generic limits:

- `maxHops`
- `maxSlots`
- `maxInstances`

M0.7-D makes those limits a first-class application control surface.

Default/full budget remains:

```text
Hops      4
Slots     6
Instances 9
```

## Frontier semantics

A bounded stop is not treated as invalid authored state.

For example:

```text
Instances = 0
      ↓
References may resolve
      ↓
Virtuals may resolve
      ↓
Instance realization stops
      ↓
budget.maxInstances
```

The useful state before the stop remains inspectable.

The application projects:

```text
Resolution Frontier
├ state
├ budget
├ usage
├ stops
└ unresolved Virtuals
```

Each stop contains the generic evidence already produced by the DAG solver:

- reason;
- node id;
- hop when applicable;
- requested cost;
- used cost;
- limit.

## Tuple-graph evidence

The Resolution graph now includes a first-class frontier node:

```text
Resolution
   └ has → Resolution Frontier
              ├ property → state
              ├ property → budget
              ├ property → usage
              ├ contains → Stop
              │             └ blocked-by → budget.max*
              └ contains → unresolved Virtual
```

This means `blocked-by` is evidence about why resolution stopped, not an authoring error.

## Application controller

`src/app/resolution-session.js` wraps the existing M0.7-C authoring session.

It delegates all Card/Pack operations to the authoring session and owns only:

- current resolution budget;
- resolution revision;
- bounded recomputation of Graph / Resolution / World views.

The Card and Pack projections remain sourced from the same authored truth as C.

## Browser surface

Resolution mode now exposes:

- Hops input;
- Slots input;
- Instances input;
- Resolve to budget;
- Full budget reset;
- Virtual-only preset;
- slot-limited preset;
- shallow-hop preset;
- usage meters;
- explicit stop reasons;
- retained unresolved Virtuals;
- authoring revision and resolution revision side by side.

The browser calls application operations. It does not implement DAG stopping rules.

## Acceptance proofs

### Runtime-budget independence

Changing budget:

- leaves `revision` unchanged;
- advances `resolutionRevision`;
- leaves Card tuples byte-for-byte equivalent;
- leaves Pack tuples byte-for-byte equivalent.

### Virtual-only resolution

With:

```text
maxHops      = 4
maxSlots     = 6
maxInstances = 0
```

Small World must:

- report unresolved World state;
- report at least one `budget.maxInstances` stop;
- retain resolved Virtual projections;
- add `blocked-by → budget.maxInstances` evidence to the Resolution graph;
- preserve authored Card and Pack truth.

### Slot-limited resolution

With `maxSlots = 3`, resolution must stop through `budget.maxSlots` after exactly three slot units are consumed.

### Hop-limited resolution

With `maxHops = 1`, resolution must expose `budget.maxHops` stops without modifying authored truth.

### Full resolution

Restoring full budget must settle the same current authored graph to the World target.

## Quality line

> A budget chooses how much reality becomes explicit now. It does not redefine what the authored world means.

And:

> An unresolved frontier is useful state with an explanation, not failed generation.

## Deliberately deferred

M0.7-D does not yet add:

- node-by-node manual stepping;
- user-selected semantic priority between frontier branches;
- persisted resolution checkpoints;
- hierarchical/local regional budgets;
- dynamic Signals driving a new resolution pass;
- full visual consolidation of the authoring workstation.

Those remain later slices. D proves the generic bounded frontier contract first.
