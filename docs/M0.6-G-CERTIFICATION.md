## Certified properties

### 1. M0.5 preservation

- digest `de96ca6e6487eba6`;

- 23 temporal entities;

M0.5 remains a frozen regression oracle rather than the target architecture.

### 2. Plain generative lifecycle

The new model uses:

```text
Definition → Template → Reference → Virtual → Instance
```

Definitions declare grammar/dimensions. Templates carry authored priors and fixed semantic facts. References bind context/boundary. Virtuals expose current possibility fields/ranges/slots. Instances are the first stage with settled runtime values.

The scoped content catalog contains:

- Personas: Bandit, Bear, Dragon;
- Biomes: Swamp, Desert, Mountains;
- Items: Sword, Staff, Shield;
- Packs: Cave, Ruin, Spire.

Clock and Hourglass use the same lifecycle.

### 3. Deterministic world replay

Certification rebuilds and resolves the horizontal world twice for each seed:

```text

42
65537
93208
99991
```

Each pair resolves to exactly equal world values, budget usage, and stop records.

The canonical full solve remains:

```text
maxHops      = 4
maxSlots     = 6
maxInstances = 9
```

and produces three Regions, three Situations, and six contained Artifact Instances.

### 4. Bounded collapse

Certification repeats seed `93208` under these budget shapes:

```text
hops 0 / slots 6 / instances 9
hops 2 / slots 6 / instances 9
hops 4 / slots 0 / instances 9
hops 4 / slots 3 / instances 9
hops 4 / slots 6 / instances 0
hops 4 / slots 6 / instances 9
```

Every repeated solve is deterministic. Reduced budgets remain unresolved at explicit frontier records; the full budget resolves. Slot and Instance usage never exceed their ceilings, and admitted hop usage is reported separately from a rejected frontier hop.

Budget exhaustion therefore means **less realization**, not invalid state or forced collapse.

### 5. Content-agnostic kernel

for game-content names including Dragon, Bear, Bandit, Cave, Ruin, Spire, Sword, Staff, Shield, Swamp, Desert, Mountains, Persona, and POI.

None occur.

The frozen `src/kernel/m0.5/` oracle is explicitly excluded because its purpose is historical behavior preservation.

### 6. Unplanned extension proof

Certification authors a new `persona.wolf` Template at test time, binds it to a Region context, compiles it through the shared lifecycle DAG, and realizes a Wolf Instance without modifying kernel or runtime code.

This demonstrates that adding an ordinary fourth Persona is a content/model action rather than a solver feature.

### 7. Generative instruments

Certification independently realizes:

- a Clock through the generic lifecycle DAG;
- an Hourglass through the same DAG, bound to the newly realized Wolf owner.

Instrument-specific content remains above the solver.

### 8. Solve / commit feedback boundary

The runtime now has an explicit staged state transition:

```text
WorldState(t)
   ↓ compile
DAG(t)
   ↓ solve
Resolved result
   ↓ commit once
WorldState(t+1)
```

Certification starts with pressure `2`, solves `3` without mutating the prior state, commits revision/tick `1` with pressure `3`, then compiles the next DAG from that committed state and solves pressure `4`.

Feedback therefore crosses a deterministic commit boundary instead of creating a cycle inside the active DAG.

### 9. Inspectability

The certified world remains readable through the four plain inspection handles:

```text
Facts
Possibilities
Lineage
Signals
```

and through a semantic `WorldGraphView` of Regions and Situations.

## What M0.6 does not claim

M0.6 deliberately does **not** claim:

- dynamic Pack-selection policy from world pressure;
- a production map renderer or geometry system;
- hundreds of content Templates;
- fully realized ClockFace/ClockHand/Hour/HourglassLock/Filter content libraries;
- final combat/event gameplay;
- production persistence/networking;
- final-scale performance.

Those are later work. M0.6 proves that they can be added above a bounded, deterministic, inspectable generative core without changing the basic modeling contract.
