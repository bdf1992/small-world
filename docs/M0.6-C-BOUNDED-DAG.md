# M0.6-C — Bounded DAG Solver

## Purpose

Introduce the first content-agnostic execution kernel for M0.6.

The solver does not know about Dragon, Persona, Cave, POI, elemental semantics, or game-specific rules. Content compiles its lifecycle onto generic nodes; the kernel only resolves dependencies under explicit budgets.

## Kernel handles

```text
Node
Graph
SolveBudget
Result
Trace
```

A Node declares:

- `id`
- upstream `inputs`
- optional `slotCost`
- optional `instanceCost`
- an `evaluate` function

The graph must be acyclic. Cycles are rejected before execution.

## Solve budget

```text
SolveBudget
├── maxHops
├── maxSlots
└── maxInstances
```

### maxHops

Limits causal traversal distance from the requested target toward its dependencies.

Distance is computed using the shortest dependency path, so converging DAGs do not become traversal-order dependent.

### maxSlots

Limits expansion of addressable compositional openings. Hitting the limit produces an unresolved frontier result.

### maxInstances

Limits crossings of the realization boundary. Upstream causes are resolved first, so `maxInstances = 0` can still return a fully resolved Virtual while refusing to materialize an Instance.

## Budget behavior

Budget exhaustion is normal control flow.

```text
resolved causes
    ↓
frontier budget reached
    ↓
unresolved result + stop reason + trace
```

The solver does not guess through missing priors and does not force realization.

## Convergence behavior

Shared dependency nodes are memoized once per solve. A converging graph therefore evaluates shared causes once rather than charging or mutating them once per incoming path.

## Dragon proof

Dragon currently compiles to:

```text
Dragon Reference
      ↓
Dragon Virtual
      ↓
Dragon Instance
```

The generic kernel executes those nodes without importing Dragon code.

Tests prove:

- the Virtual can be requested with zero Instance budget;
- requesting the Instance with zero Instance budget resolves the Virtual and stops at realization;
- insufficient hop budget stops at the missing causal frontier;
- sufficient budget realizes exactly one deterministic Dragon Instance;
- repeated solves with the same inputs replay identically.

## Explicitly deferred

This pass does not yet make Packs or Regions. `maxSlots` is tested against a generic compositional DAG so the budget contract exists before Cave/Ruin/Spire use it.

M0.6-D will use these same primitives for a small Region graph and Pack/Situation composition.
