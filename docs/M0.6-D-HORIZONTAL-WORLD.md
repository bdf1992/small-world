# M0.6-D — Horizontal Small World

## Purpose

Prove that the new lifecycle and bounded DAG solver can generate a small recognizable world across multiple content families without adding content-specific behavior to the kernel.

## Region model

The simulation map is a graph, not a geometry contract.

```text
Region
├── extent
├── boundary.neighbors[]
├── attributes
├── artifactId
└── slots
```

The canonical test world contains three reciprocal Region nodes:

```text
Swamp ─── Desert
   \       /
    Mountains
```

No `x`, polygon, hex, Voronoi, or other renderer geometry is required. Presentation may later project the same graph into any useful spatial representation.

Each Region is grounded by a realized Biome Artifact whose settled elemental field becomes contextual input for contained Card/Pack Virtuals.

## Authored catalog

M0.6-D contains the complete scoped authoring set:

- Personas: Bandit, Bear, Dragon
- Biomes: Swamp, Desert, Mountains
- Items: Sword, Staff, Shield
- Packs: Cave, Ruin, Spire

These are Templates above the solver.

## Canonical Pack references

This pass deliberately uses explicit authored references:

```text
Swamp     → Cave
Desert    → Ruin
Mountains → Spire
```

Choosing which Pack should occupy a Region is a separate policy/generation problem and is not hidden inside this milestone.

Each Pack exposes two compositional slots:

```text
guardian → Persona candidate field
 treasure → Item candidate field
```

The slot pipeline is:

```text
Pack Virtual
   ↓
Slot choice           (slot budget)
   ↓
Card Virtual
   ↓
Artifact Instance     (instance budget)
```

After all required members are realized, the Pack Virtual crosses its own realization boundary and becomes a Situation Instance.

## Situation / POI boundary

Runtime:

```text
Situation = realized Pack composition
```

Spatial/UI projection:

```text
POI = address/presentation of that Situation on the map
```

The horizontal test intentionally does not create a second `POI` entity merely to display a Situation.

## One world DAG

All three Situations are compiled into one target graph, so budgets apply globally rather than once per Region.

Canonical full budget:

```text
maxHops      = 4
maxSlots     = 6
maxInstances = 9
```

The result contains:

- 3 starting Biome Artifact priors;
- 3 Regions;
- 3 realized Situations;
- 6 realized member Artifacts;
- 6 consumed compositional slots;
- 9 realization crossings inside the solve.

Starting Biomes are treated as prior world state for this solve and are therefore not charged to its materialization budget.

## Bounded behavior

Tests prove:

- smaller slot budget leaves Pack Virtuals visible and the world unresolved;
- zero Instance budget still explores Pack and Card Virtuals;
- shallow hop budget stops before unsupported causal depth;
- full budget deterministically realizes the complete small world;
- rebuilding the graph with the same seed replays the exact world result.

## Next boundary

M0.6-E moves Clock and Hourglass onto the same generative model. They should cease to be privileged concepts that only exist as legacy runtime classes: their Definitions, Templates, References, Virtuals, and Instances should be inspectable like other mechanically addressable content.
