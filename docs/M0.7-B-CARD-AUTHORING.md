# M0.7-B — Card Authoring

Status: **alpha / stacked on M0.7-A**

This slice turns `Card` from a fixed example into a plain authoring handle with a real lifecycle.

## Quality lines

> Card data is authoring data. Runtime lifecycle objects are compiled outputs, not editor state.

> A Card edit is not real until the same Card can be contextualized as a Reference, represented as a Virtual, and realized as an Instance.

> Pack wiring does not belong in the Card editor. Cards advertise possibility; Packs compose Cards through Requirements in M0.7-C.

## Card draft contract

A draft is intentionally plain serializable data:

```text
Card
├── id
├── grammar
├── fixed
├── priors
├── rules
└── slots
```

Supported grammars in this slice:

- `Artifact/Persona`
- `Artifact/Item`
- `Artifact/Biome`

The Card library validates required identity fields, identifier shape, contextual affinities, weighted possibility support, and non-negative finite weights before compilation.

## Operations

The application authoring session now supports:

- create Card
- clone Card
- select Card
- rename non-canonical Card
- delete non-canonical Card
- edit fixed identity fields
- edit weighted priors
- edit contextual affinity
- reset to the canonical authoring baseline

`persona.dragon` remains protected as the canonical parity Card while M0.6/M0.7 are stacked. It can be edited but not renamed or deleted from the draft session.

## Compilation path

```text
plain Card draft
      ↓ validate
immutable Template
      ↓ bind Mountains
Reference
      ↓ contextualize
Virtual
      ↓ deterministic realization
Instance
```

The resolved preview is not a browser approximation. It comes from the application Card compiler and uses the same deterministic address/weighted-choice primitives as the world engine.

## Canonical authoring proof

Clone:

```text
persona.dragon
      ↓ clone
persona.ice-dragon
```

Then edit:

```text
species = Ice Dragon
rarity  = T5 100%
element = contextual / strong
```

Against Mountains at seed `93208`, the draft must retain Dragon's authored age and temperament possibility trees, expose a contextual element Virtual, and realize as an `Ice Dragon` Instance with T5 rarity and its own stable instance id prefix.

This is deliberately not yet inserted into Spire. M0.7-C owns the Requirement/port connection that lets a Pack select an arbitrary Card.

## Browser surface

The Card mode now contains a Card library above the tuple-tree projection:

```text
Card selector
Id / grammar
New · Clone · Rename · Delete

Draft                         Resolved preview
fixed fields                  Reference
contextual affinity           Virtual possibilities
weighted priors               Instance facts
```

Changing a Card field goes through `/api/authoring/*` and recompiles server-side authoring state. Browser code owns presentation and gestures only.

## Acceptance

`npm run verify:cards` must prove:

1. a new Persona Card validates and resolves;
2. a cloned Dragon preserves all authored possibility fields;
3. the clone can become `Ice Dragon` without mutating canonical Dragon;
4. contextual Mountains weighting affects its Virtual;
5. Card CRUD increments authoring revision and preserves stable selection;
6. Item Cards use the same authoring library/compiler;
7. invalid identifiers, missing required identity, negative weights, and zero-support possibility sets are rejected;
8. canonical Dragon cannot be renamed or deleted;
9. Card CRUD works through the HTTP authoring port;
10. Card editor browser JavaScript parses successfully;
11. all prior M0.5/M0.6/M0.7-A regression gates remain green.

## Explicitly deferred to M0.7-C+

- arbitrary Card candidate insertion into a Pack;
- Requirement query/discovery over the Card library;
- typed Pack ports and connection gestures;
- Card persistence to repository files;
- arbitrary prior/candidate creation and removal;
- editable Rules;
- runtime Signal authoring;
- full visual consolidation.
