# M0.7-G — Shared Visual Language

Status: **implementation slice in progress; owner acceptance pending**

M0.7-G gives the playable world and the authoring/resolution workbench one visual grammar without creating a second semantic model in the browser.

The underlying product already has distinct kinds of truth:

```text
World / Region / Situation / Artifact
Instrument
Card / Pack / Requirement
Resolution / Virtual frontier
Evidence / Lineage / Ledger
Dynamic signal / temporal transfer
```

Before G, those surfaces had useful but separate styling conventions. G makes them visibly related.

## Quality lines

> **The same semantic thing should look like the same kind of thing wherever it appears.**

> **Presentation may style declared meaning; it may not infer or invent meaning.**

> **World state stays primary. Authoring and resolution reveal the apparatus behind it rather than replacing the world with a dashboard.**

> **Color is secondary evidence. Frame, label, rhythm, and object treatment must carry the distinction too.**

## Visual domains

G defines six presentation domains:

| Domain | Means | Examples |
| --- | --- | --- |
| `world` | settled or currently observed world state | map, field topology, selected cell, Region |
| `instrument` | diegetic machinery that measures or transfers world state | Clock, Hourglass |
| `authoring` | declared construction truth | Card, Pack, Requirement wiring |
| `resolution` | unsettled computation / bounded collapse | frontier, spawn proposition, Virtual stop |
| `evidence` | explanation, receipts, provenance | Inspector, lineage, ledger, Authoring Document |
| `dynamic` | world motion or transfer | temporal transfer, Signal / Influence motion |

The domains are deliberately not lifecycle stages and not new engine kinds.

## Declarative contract

Static surfaces declare their domain:

```html
<section class="sw-frame" data-sw-domain="instrument">...</section>
```

Projected objects may declare a presentation kind:

```html
<button class="sw-object-link" data-sw-kind="Artifact">...</button>
```

The shared stylesheet consumes only these declarations.

`web/world-language.css` must not inspect object ids, parse labels, or duplicate application rules.

## Shared frame grammar

Every `sw-frame` gets the same structural treatment:

- a quiet top authority rail;
- a small textual domain mark;
- a domain accent;
- the same corner/border cadence;
- no change to interaction ownership.

This means a Clock panel and a Resolution frontier remain visually related as parts of one game/workbench while still reading as different kinds of surfaces.

## Shared object grammar

World Region cards, landed members, and lineage steps use one object cadence:

- left semantic rail;
- stable object spacing;
- optional `data-sw-kind` accent;
- identity remains text-first;
- ids remain available but subordinate.

A landed Artifact therefore reads as an object both in World mode and when inspected backward through lineage.

## Lifecycle grammar

F already exposes the true lifecycle:

```text
Definition → Template → Reference → Virtual → Instance
```

G renders that as a connected sequence through `sw-lifecycle` and `data-sw-stage`.

The browser is still only rendering F's supplied lifecycle data.

## Authoring projection domain

The Authoring & Resolution main frame changes visual domain with the selected projection:

```text
Card       → authoring
Pack       → authoring
Graph      → evidence
Resolution → resolution
World      → world
```

`web/world-language.js` performs only this presentation synchronization and stamps generic presentation hooks on already-rendered World cards/landed members.

It does not call an application mutation endpoint and does not calculate world truth.

## World-first behavior

The playable parity surface remains the main world workstation.

G does not replace the large field with a generic graph or editor. Instead it gives the existing world workstation a visible grammar:

- field and map are `world`;
- Clock and player Hourglass are `instrument`;
- spawn proposition and generative overlay are `resolution`;
- temporal transfer is `dynamic`;
- inspector and ledger are `evidence`.

This preserves the M0.5 whole-shape lesson while making the M0.6/M0.7 apparatus legible.

## Non-authority rule

No file under `src/` is required for G.

That is intentional.

The visual language is allowed to:

- style existing projections;
- add semantic presentation hooks;
- synchronize a view's domain label with the selected projection;
- improve legibility.

It is not allowed to:

- choose Pack members;
- resolve Virtuals;
- invent provenance;
- mutate world or authoring state;
- reinterpret budget stops;
- create a new domain model parallel to application projections.

## Verification targets

`npm run verify:visual` must prove:

1. both primary workbench pages load `world-language.css`;
2. the authoring page loads `world-language.js`;
3. the shared stylesheet declares all six visual domains;
4. the playable world explicitly marks World, Instrument, Resolution, Evidence, and Dynamic surfaces;
5. authoring explicitly marks Authoring, Resolution, and Evidence surfaces;
6. active authoring projection maps only to a presentation domain;
7. the visual synchronizer contains no `fetch` or application mutation call;
8. F lineage output carries declared object/lifecycle hooks;
9. shared visual assets are served by the workbench over HTTP;
10. application projection remains version 6 and authored/runtime revisions are unchanged by requesting visual assets;
11. all inherited M0.5 / M0.6 / M0.7-A..F tests remain green.

## Deliberately deferred

G does not attempt:

- final art direction;
- sprite/icon packs;
- a full map renderer rewrite;
- animation choreography;
- responsive redesign beyond the existing workbench behavior;
- accessibility certification;
- theme/plugin architecture;
- runtime persistence;
- M0.8 world-motion mechanics.

G is the shared grammar needed before those layers can become richer without drifting apart.
