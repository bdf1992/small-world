# M0.6-I — M0.5 Whole-Shape Parity Restoration

## Ruling

The merged `0.6.0` architecture is **not** accepted as a whole-product successor to the frozen M0.5 vertical slice.

The prior acceptance process proved individual M0.6 components and preserved an exact M0.5 regression digest, but it did not prove that the product surface composed those capabilities together. The result retained the new lifecycle, bounded solver, Regions, Packs, instruments, and inspection as separate capabilities while dropping most of the live spatial/temporal interaction that M0.5 already demonstrated.

This pass treats the frozen M0.5 vertical slice as **executable product canon**, not merely a regression oracle.

## Parity rule

For every player/developer-visible capability in M0.5, M0.6 must answer:

1. What application operation owns it?
2. What state/projection exposes it?
3. What interface gesture exercises it?
4. What deterministic test proves it?
5. If the implementation remains transitional M0.5 code, what seam allows later replacement without changing the interface contract?

A file, class, or unit test existing somewhere in the repository is not parity.

## Restoration architecture

Parity is restored through an application/session boundary rather than by putting simulation logic back into the browser.

```text
transitional M0.5 mechanics        M0.6 generative mechanics
            │                                │
            └────────────┬───────────────────┘
                         ▼
               application/session API
                         │
             serializable projections
                         │
             ┌───────────┴───────────┐
             ▼                       ▼
       diegetic workbench          tests
```

The legacy M0.5 kernel is allowed behind the application seam during parity restoration because it is already the frozen executable behavior. The interface must not import it directly. Later M0.6-native replacements can move capabilities across the seam without changing the workbench contract.

## First restoration slice

The first slice must expose, through the application layer:

- root/active RFC field state;
- cells, polygons, adjacency, resolution state, probability/entropy, nuclei, roots, collisions, external and temporal pressure;
- child previews;
- generation step / finish / replay;
- select / dive / back;
- Clock state / advance / flip and relation inspection;
- player Hourglass state / spend / flip;
- temporal biome/entity hourglasses;
- spawn candidate scores;
- tick results and ledger;
- invariants and deterministic digest.

The browser then consumes only this projection/actions contract.

## Release correction

Until this matrix is green as a composed experience, `main` commit `c41f2acb24b059ae4a4419d057fcbadf0ac73338` should be understood as the **M0.6 architecture baseline**, not proof of M0.5 whole-shape parity.

Do not begin M0.7 product work until parity restoration is accepted.
