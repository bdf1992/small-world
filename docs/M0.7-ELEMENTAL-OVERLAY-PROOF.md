# M0.7 Elemental Overlay Proof

Status: implementation candidate; owner acceptance pending.

This slice implements only the smallest mathematical proof behind the clarified elemental glossary.

## Canonical structure

There is one eight-element ring:

```text
Void → Fire → Chaos → Ground → Aether → Water → Order → Sky → Void
```

There is one Relation Wheel:

```text
 0  Is
+1  Affinity
+2  Anchor
+3  Vice
 4  Nemesis
-3  Conflict
-2  Need
-1  Wants
```

Each participating Element rotates that same wheel to itself and contributes the resulting reading at its own weight.

## Proof case

```text
Fire  = 10
Water = 1
```

The default Profile is:

```text
10 × rotate(Relation Wheel, Fire)
+
 1 × rotate(Relation Wheel, Water)
```

Nothing selects Fire as a single winning identity and discards Water.

Representative overlaid readings are:

```text
Fire  ← Fire:Is ×10        + Water:Nemesis ×1
Water ← Fire:Nemesis ×10   + Water:Is ×1
Chaos ← Fire:Affinity ×10  + Water:Conflict ×1
```

The implementation preserves both raw weights and normalized shares so later resolvers can choose the appropriate measurement without losing the authored ratio.

## Boundary

This slice does **not** define Property deformation, Clock/Hourglass propagation, State mutation, combat, Token semantics, Sprite generation, or UI behavior.

Those later systems may read or transform the default Profile through admitted rules, but they must not mutate the canonical Relation Wheel itself.

## Evidence

`npm run verify:elements` proves:

1. the canonical ring and Relation Wheel are fixed;
2. Fire and Water are rotations of the same wheel;
3. `Fire 10 / Water 1` retains both weighted contributions;
4. scaling `10/1` to `20/2` preserves relative shares while preserving the different absolute total;
5. invalid/unknown elemental compositions are refused.

Passing this proof is machine evidence only. It does not constitute owner acceptance of the M0.7 glossary, work request, or implementation.
