## QA findings repaired in RC.1

### 1. Lifecycle identity custody

`createInstance()` previously accepted a settled payload after writing lifecycle fields, allowing the payload to overwrite `stage`, provenance IDs, and grammar.

RC.1 makes lifecycle identity constructor-owned. Settled runtime facts may extend an Instance but may not rewrite what lifecycle object it is or where it came from.

### 2. Solver budget custody

Node evaluators previously received the live mutable solver budget state. Content code could therefore mutate counters/stops that the kernel is responsible for enforcing.

RC.1 keeps live budget state private to the solver. Evaluators receive only resolved `inputs` and caller `context`. Node `slotCost` and `instanceCost` are also validated as non-negative integers at graph construction.

### 3. Causal inspection

`WorldGraphView` previously exposed Region topology and backing Artifact IDs without the Region attributes that contextualize downstream Virtual possibility fields.

RC.1 includes Region attributes in inspection so owner QA can connect world context to resulting possibilities.

### 4. Direct exercise path

RC.1 added:

```bash
npm run world
```

with `--seed`, `--hops`, `--slots`, and `--instances` controls.

## RC.2 — Diegetic workbench and interface boundary

Owner feedback established that the terminal runner is useful evidence but is below the intended interaction quality line. RC.2 therefore adds:

```bash
npm run workbench
```

which serves a dependency-free browser workbench at `http://127.0.0.1:4173`.

The workbench is deliberately lightweight:

- the abstract world map is primary;
- Region topology is rendered as the navigable surface;
- realized Situations appear within Regions;
- Region, Situation, Artifact, and Virtual objects all use the same selection and inspector grammar;
- the inspector progressively discloses `Surface`, `Possibility`, and `Lineage`;
- reduced-budget stops and unresolved Virtuals remain visible as the frontier;
- seed and solve budgets remain adjustable without introducing UI-owned world behavior.

### Separation-of-concerns contract

RC.2 introduces `src/app/world.js` as the application port between world machinery and interfaces.

```text
kernel + model + runtime + content + inspection
                    ↓
              src/app/world.js
                    ↓
          serializable projection
             ↙             ↘
      CLI adapter          web adapter
```

The application projection normalizes interface-facing objects to one contract:

```text
key
id
kind
label
stage
grammar
regionId
facts
possibilities
lineage
children
```

The browser does not import kernel, model, runtime, or content modules and does not choose game outcomes. Map layout, typography, disclosure, and interaction are presentation concerns only.

This boundary is intended to remain compatible with future canvas, board, replay, debug, agent, and game-facing projections.

## Deferred beyond M0.6

### Budget allocation policy

When a global budget cannot satisfy every eligible branch, current traversal/input ordering determines which branch consumes capacity first. This is deterministic but not yet a semantic priority policy. M0.7 should make allocation/importance explicit before world scale increases.

### `Signals` terminology

M0.6 inspection currently uses **Signals** for summarized solver trace/stop information. The emerging M0.7 design may introduce world-level signals as actual transmitted influence. Those concepts should be separated or renamed before signal propagation becomes a first-class mechanic.

### Rich spatial layout

RC.2 uses a generic presentation-only radial layout for Regions. It intentionally does not introduce geometry, procedural cartography, camera systems, or semantic layout rules into the engine. Those can evolve independently after the application projection proves stable.
