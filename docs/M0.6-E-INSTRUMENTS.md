# M0.6-E — Generative Instruments

## Purpose

Prove that Clock and Hourglass are ordinary users of the shared generative model rather than privileged runtime-only classes.

Both now follow:

```text
Definition → Template → Reference → Virtual → Instance
```

and can compile through the same bounded lifecycle DAG used by other content.

## Clock

The Clock Definition owns the mechanical shape:

```text
Clock
├── Face slot      → ClockFace
├── Hands slot     → ClockHand 1..N
├── Hours slot     → Hour × 12
├── tick/state dimensions
└── operational stats
```

The Standard Clock Template fixes structural facts such as 12 positions and 60 ticks per cycle. It does not contain exact runtime tick/cycle state or a settled `advancePerTurn` stat.

A Clock Virtual exposes possible orientation and advance rate plus unresolved component slots. The Clock Instance is the first object with exact orientation, advance rate, cycle, and tick state.

## Hourglass

The Hourglass Definition owns the topology:

```text
Upper
  ↓
Neck
  ↓
Lower

Timeless = outside the glass
```

and component slots:

```text
Lock
Filter
```

Capacity, crossing rate, integrity, grain-inside, and timeless grain are Stat dimensions. The Standard Hourglass Template declares rarity priors and derivation rules; it does not settle capacity.

An Hourglass Reference binds the instrument to an owner. The Virtual preserves that owner boundary and exposes rarity/capacity/rate ranges. The Instance is the first stage with a selected rarity, exact capacity/crossing rate/integrity, and concrete region state.

## Component definitions

M0.6-E also establishes Definition grammars for:

- `Instrument/ClockFace`
- `Instrument/ClockHand`
- `Instrument/Hour`

They are not populated with a large content library yet. Their purpose is to make future special faces, hands, and hours normal slot content instead of future engine exceptions.

## Progressive realization

A realized parent Instrument may still contain unresolved component slots. This is intentional:

```text
Clock Instance
└── Hand slot → Virtual / unresolved
```

The parent can exist without forcing every nested possibility to collapse.

## Shared execution

`compileLifecycleGraph` turns any Reference + virtualizer + realizer into the same generic three-stage executable DAG:

```text
Reference → Virtual → Instance
```

Tests prove zero Instance budget resolves the Clock Virtual but refuses Clock realization, while sufficient budget realizes an Hourglass through the same solver used by Dragon.
