# M0.7 — Owner QA / Release-Candidate Walkthrough

Status: **machine candidate verified; owner acceptance required**

This is the human acceptance boundary for the complete M0.7 A–G stack.

It deliberately combines two questions that should not be confused:

1. **Does the system still behave like Small World?**
2. **Does the new authoring/resolution apparatus feel like a coherent extension rather than a replacement product?**

Machine verification can establish the first partially. Only owner use can establish the second.

## Acceptance rule

Do not infer acceptance from:

- opening the workbench;
- running the tests;
- asking for a merge preview;
- saying a particular screen looks better;
- approving one isolated slice.

M0.7 owner acceptance should be an explicit product-level statement after this walkthrough.

Suggested acceptance wording:

```text
I accept M0.7 A–G as the next Small World baseline.
```

Anything less specific remains review feedback, not release acceptance.

# 1. Start from the world, not the editor

Run:

```bash
npm run workbench
```

Open the root workbench `/` first.

### Floor check

Before looking at any M0.7 authoring feature, verify the restored M0.5 whole-shape interaction still reads as the product:

- the large world field dominates the screen;
- Center / Barrier / Edge remain visible computational territory rather than a decorative background;
- cells, nuclei, frontier/wave behavior and world resolution are legible;
- `Step Wave` changes the world incrementally;
- `Resolve All` settles the current field;
- a selected cell produces meaningful inspectable state;
- `Dive Into Cell` enters recursive child state;
- `Back` returns to the parent state;
- breadcrumb/depth remains understandable;
- Elements / Entropy / Roots / Pressure / Time views each reveal a distinct useful projection;
- the Clock is visibly part of the world rather than generic chrome;
- `Flip Day/Night` changes orientation without pretending to advance time;
- `Cross Tick + Resolve Time` advances actual temporal state;
- biome temporal state is visible after a tick;
- spawn proposition, temporal transfer and player Hourglass still feel coupled to the field;
- the ledger reads as evidence of world motion, not a debug dump.

### Reject M0.7 immediately if

- the map no longer feels primary;
- the authoring apparatus has displaced the world interaction grammar;
- instruments feel like detached dashboard widgets;
- recursive exploration is harder to understand than M0.5;
- a major M0.5 capability is present only in code/tests but effectively unavailable in the interface.

---

# 2. Judge the G visual language in the playable world

The small domain labels are meant to expose system role without becoming dev chrome.

Check the following relationships:

```text
World       = field / topology / selected place
Instrument  = Clock / Hourglass
Resolution  = proposition / generative frontier
Dynamic     = temporal transfer
Evidence    = inspector / ledger
```

Ask:

- Do those categories help orient the eye?
- Are they quiet enough that the world still wins visually?
- Do Clock and Hourglass feel like the same family of diegetic machinery?
- Does Resolution look unsettled without looking disabled or broken?
- Does Evidence look explanatory rather than editable?
- Would you want these cues to survive into a more polished roguelike skin?

### Reject G if

- the domain labels feel like developer annotations pasted onto the game;
- color is doing all the semantic work;
- panel rails create more clutter than orientation;
- the framing makes the screen feel more like an admin dashboard than a world workstation.

# 3. Enter Authoring & Resolution

Open `/authoring`.

The intended relationship is:

```text
Card / Pack author meaning
        ↓
Graph exposes structure
        ↓
Resolution shows bounded collapse
        ↓
World shows the landed result
        ↓
Lineage can walk backward to authored custody
```

The editor is not a second game and not a second runtime.

## Card proof

1. Clone `persona.dragon` as `persona.ice-dragon`.
2. Change species to `Ice Dragon`.
3. Inspect weighted and contextual fields.
4. Change a weight and verify the resolved preview responds.
5. Change elemental affinity and verify the possibility field changes without mutating unrelated authored truth.

Check whether the Card editor feels like a plain handle over a richer model rather than a schema form.

## Pack proof

1. Open Pack.
2. Connect Ice Dragon to `guardian`.
3. Focus Ice Dragon as the guardian candidate.
4. Confirm the Requirement remains visibly `Artifact/Persona × 1`.
5. Confirm Treasure remains independently wired.

The Pack should feel like a small circuit of typed roles, not an arbitrary list of ids.

# 4. Resolution proof

Open Resolution.

### Full budget

Confirm the world resolves completely.

### Virtual-only budget

Set:

```text
Hops      4
Slots     6
Instances 0
```

Expected:

- authored Card/Pack truth does not change;
- world is explicitly unresolved;
- Virtuals remain inspectable;
- stop reason says `budget.maxInstances`;
- no landed Instance is fabricated from a Virtual.

### Restore full budget

Reset to full budget.

Expected:

- the landed world returns;
- authored revision remains the same;
- only resolution revision changes.

This should make bounded computation feel like a lens over the same authored world, not a destructive partial save.

# 8. M0.7 product-level decision

M0.7 should pass only if all of the following are true:

- M0.5 world interaction remains the product floor;
- M0.6 bounded generative architecture is visible without replacing that floor;
- Cards are a pleasant authoring handle;
- Packs communicate typed composition;
- Resolution communicates bounded possibility without invalid-state anxiety;
- Authoring Documents feel like useful portable authored truth;
- realized world objects can explain their custody backward;
- the shared visual grammar improves coherence;
- the interface still feels like a world / roguelike workstation rather than a generic developer dashboard;
- no feature requires the browser to invent semantic truth.
