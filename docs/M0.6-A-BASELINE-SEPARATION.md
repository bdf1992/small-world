# M0.6-A — Baseline Preservation and Separation

## Purpose

Preserve the executable M0.5 vertical-slice behavior before introducing the M0.6 generative model or bounded DAG solver.

This pass establishes a regression seam, not the final architecture.

## Separation performed

The M0.5 non-presentation code has been mechanically extracted from the browser prototype into `src/kernel/m0.5/` and loaded without a DOM.

`src/runtime/m0.5-baseline.js` owns execution of the baseline scenario and converts the extracted mechanics into a stable regression snapshot.

`tests/m0.5-baseline.test.js` requires exact deep equality with the frozen fixture.

This is intentionally transitional. The extracted M0.5 module still contains several concerns that M0.6 will separate further, including field generation, temporal transfer, spawn-family policy, and legacy POI semantics. Moving those concepts now would make preservation and redesign happen in the same change.

## Pass condition

M0.6-A passes when the separated Node execution returns the exact frozen M0.5 snapshot under CI.

No numerical tolerance is used. Any output change must either be repaired or explicitly versioned as a later M0.6 behavior change.

## Next boundary

2. introduce the M0.6 model independently (`Definition → Template → Reference → Virtual → Instance`);
3. use Dragon as the first golden modeled object;
4. do not retrofit Dragon/Pack semantics into the legacy M0.5 extractor.
