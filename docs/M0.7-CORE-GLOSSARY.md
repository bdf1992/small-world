# M0.7 Core Glossary

Status: design candidate from owner glossary review; owner acceptance pending.

This glossary is intentionally small. It defines the minimum language needed to reason about elemental character, Artifact collapse, measured state, topology, traversal, crossings, and presentation. It does not add new gameplay ontology.

It extends `M0.7-MINIMAL-ARTIFACT-GRAMMAR.md` and must not reintroduce the speculative semantic fields removed by that reset.

## Element

One of the eight fixed positions in the elemental ring:

```text
Void → Fire → Chaos → Ground → Aether → Water → Order → Sky → Void
```

The ring is one shared cyclic relation system. Elements are not eight unrelated stat fields.

## Elemental Identity

The orientation/phase anchor used to read the elemental ring for an Artifact.

In the current proof, one Element occupies the `Is` / origin seat for each Profile reading. The rest of the ring is then read by relative offset from that seat.

Example with `Fire` at `Is`:

```text
Fire   = Is
Chaos  = Affinity
Ground = Anchor
Aether = Vice
Water  = Nemesis
Order  = Conflict
Sky    = Need
Void   = Wants
```

Changing Elemental Identity rotates the same relation shape; it does not load a separately authored profile.

The current contract fixes one origin seat per Profile reading. It does **not** yet claim that every Artifact must forever have exactly one elemental contribution. Additional elemental participation may be expressed through Attributes, Properties, measured State, or later admitted rules without duplicating the canonical Profile shape. Do not invent a second profile system merely to represent variation.

Use **Elemental Identity** when ambiguity is possible. It is distinct from an Artifact's deterministic **instance identity** / unique collapse address.

## Profile

The canonical directed relation shape around an Elemental Identity.

The Profile assigns the relative roles:

```text
 0  Is
+1  Affinity
+2  Anchor
+3  Vice
 4  Nemesis
-3  Conflict
-2  Need
-1  Wants
```

Conceptually:

```text
canonical elemental relation shape
+ Elemental Identity orientation
= Profile
```

A Profile is the shared structural character of the eight-element ring. Properties and measured conditions may vary how that Profile is applied without redefining the ring itself.

## Attribute

A weighted elemental relation expressed through an Artifact's Profile.

Attributes are the Artifact's usable elemental character: the relation roles and weights through which it participates in Clock, Hourglass, Grain, Artifact-to-Artifact, and other elemental interactions.

An Attribute is not an arbitrary root field such as age, mobility, moisture, race, material, or body plan.

A useful reading is:

```text
Elemental Identity
      ↓ rotates
Profile
      ↓ supplies relation roles
Attributes
      = current weights / deltas on those relations
```

## Property

An admitted rule or configuration that changes how an Artifact participates in resolution.

A Property may vary, constrain, gate, grant, transform, or interpret Attributes, Stats, Relations, Crossings, or other admitted behavior. It may be persistent or conditionally active.

Properties are not forced into a one-way hierarchy. A rule may read a Statline or measured State and activate a Property; that Property may then alter an Attribute or affect later resolution.

## Stat / Statline

A **Stat** is a measured value. A **Statline** is an addressable collection or shape of measured values.

Stats are part of what can be measured about the current system. They are not required to be terminal outputs or scalar-only leaves.

Rules may read a Stat or Statline as evidence for later resolution. For example, a measured threshold may satisfy a condition that admits or activates a Property. The measurement does not itself mutate the world; an admitted rule interprets it.

## State

The measured record of what is true at a particular time/resolution point `T`.

State is evidence. State is not the rule that changes the world.

Conceptually:

```text
State(T)
  ↓ read by admitted rules / Relations / Properties
proposed effects
  ↓ constraints + propagation + collapse
State(T+1)
```

State may record Elemental Identity, active Attributes, active Properties, Statline, Relations, Positions, Clock/Hourglass condition, and other resolved facts. This is not a frozen storage schema.

A statement such as "State gives an Attribute" is therefore shorthand for: a rule reads the measured State, that condition admits an Attribute-changing effect, resolution settles it, and the next State records the result.

## Address

A stable referent within an addressable structure.

An Address need not be geometric. A Clock Tick, Hourglass side, Neck, POI, Zone boundary, threshold, Relation endpoint, or Artifact may be addressable.

## Position

Where an entity currently occupies an addressable structure.

Position is measured as part of State.

## Relation

An admitted typed and weighted connection between addressable things.

Relations may be derived from relative structure, points, boundaries, Zones, Attributes, State, constraints, and available resolution budget.

Keep the unresolved and admitted forms distinct:

```text
relative structure
      ↓ weighted / constrained possibility
Virtual<Relation>      candidate / unresolved connection
      ↓ admission
Relation               connection admitted by the current solve
      ↓ traversal weight / cost / character
weighted Relation
      ↓ optional deeper collapse
Artifact.Road          materialized addressable connection
```

The exact weighting can itself depend on Attributes and current State. A Relation does not need to become an Artifact merely to exist. Artifactization is one possible deeper resolution of the connection.

## Traversal

Actual movement through admitted topology from one addressable Position toward another.

Traversal is not teleportation. The entity moves through the structure connecting the old and new addressable positions unless a future explicit mechanic defines another traversal rule.

## Crossing

A witnessed passage during Traversal through a meaningful boundary into a newly addressable State or Position.

Examples native to the current design shape include:

```text
Clock Hand crosses Tick
Grain crosses Hourglass Neck
Persona crosses Zone boundary
measured value traverses and crosses a Threshold
```

A State delta must not masquerade as a Crossing. The relevant entity/value must actually traverse the admitted structure and pass the boundary.

A Crossing is a causal resolution point: rules, Properties, Relations, constraints, and propagation may react before the next State settles.

## Artifact

An addressable thing in the world/system.

An Artifact may remain unresolved, partially resolved, or realized. Artifact type describes what an Artifact may become; it does not imply a matching Card.

## Virtual

A valid unresolved or partially resolved possibility.

Virtual state is first-class. Lack of resolution budget does not make the possibility invalid.

## Instance

A sufficiently collapsed realization of a Virtual possibility at an addressable collapse position.

Instance identity is deterministic and includes collapse address where needed to distinguish repeated same-type siblings. This is separate from Elemental Identity.

## Collapse

Budgeted resolution that makes Virtual possibilities more specific while preserving unresolved frontier when budget or constraints stop further resolution.

Collapse may resolve type, topology, Elemental Identity, Tokens, Relations, composition, or other admitted state without requiring every dimension to settle at once.

## Budget

The explicit limit on how much resolution may occur.

Existing dimensions include:

```text
maxHops      → relation depth
maxSlots     → opened composition edges
maxInstances → Virtual → Instance materializations
```

Budget changes resolution depth, not authored meaning or validity.

## Card.Artifact

The active generator of Artifact possibilities.

```text
Card.Artifact
    ↓
Virtual<Artifact>
    ↓ weighted / constrained collapse
Artifact.<Type>
    ↓
Instance<Artifact.<Type>>
```

A type does not require a matching Card. There is no required `Card.Persona`, `Card.Item`, or `Card.Biome` symmetry.

## Pack

A composition of possibilities, Artifacts, and Relations used to author or constrain a local resolution context.

Pack is a composition mechanism, not a parallel runtime.

## Token

A weighted semantic candidate available during collapse.

Tokens may help resolve, refine, name, or configure an Artifact. A Token is not itself an Attribute, Property, Stat, or State.

Concrete Token vocabulary and eligibility remain deliberately open.

## Sprite

A generative visual projection of resolved Artifact State.

Sprite projection may select a base image, recolor/palette-shift it, replace parts, add overlays, vary pose/orientation, or otherwise adapt presentation from Artifact type, Elemental Identity, Attributes, Tokens, Properties, State, and presentation context.

Sprite output is downstream presentation. Visual projection must not silently become authoritative simulation State.

## Core invariants

1. **One elemental ring.** There are exactly eight shared elemental positions.
2. **One canonical Profile shape.** Elemental Identity rotates/orients that shape; do not author eight unrelated profiles.
3. **One origin per Profile reading, not one-element dogma.** The current proof resolves one `Is` seat at a time while leaving additional elemental participation to Attributes, Properties, State, or later admitted rules.
4. **Elemental Identity and instance identity are different.** One orients elemental character; one uniquely identifies a realization.
5. **Attributes are weighted elemental character.** Do not use `Attribute` as a dumping ground for arbitrary semantic root fields.
6. **Properties change participation in resolution.** They may vary, constrain, gate, grant, transform, or interpret admitted behavior.
7. **Stats are measurements.** Rules may read them and later resolution may change them; they are not mutation authority by themselves.
8. **State is the measured record.** State says what is true at `T`; rules explain change toward `T+1`.
9. **Crossings require traversal.** Do not teleport between addressable states and call the delta a Crossing.
10. **Relations may remain derived.** `Virtual<Relation>` → admitted/weighted `Relation` → optional `Artifact.Road` are different resolution depths of compatible structure.
11. **Budget reduces resolution, not validity.** Unresolved frontier remains valid first-class state.
12. **Presentation is downstream.** Generative Sprite variation may reflect resolved State but cannot silently mutate it.
13. **Keep the why.** State should remain inspectable back through the Relations, Traversals, Crossings, Properties, measurements, constraints, and collapse decisions that produced it.

## Deliberately soft seams

These remain intentionally unresolved until implementation proves a stronger contract is needed:

- concrete Token vocabulary and Token Pack semantics;
- exact policy/threshold for Relation materialization into Artifacts such as Roads;
- complete Property / Statline / Attribute rule language;
- whether every traversable Relation needs an explicit intermediate path Address;
- whether an Artifact may combine multiple elemental contributions beyond the one-origin Profile reading, and exactly how such contributions compose;
- detailed Sprite composition and fallback grammar;
- type-specific semantic content.

Do not fill these seams with speculative fields merely to make examples look complete.
