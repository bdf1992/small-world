# M0.7 Core Glossary

Status: design candidate from owner glossary review; owner acceptance pending.

This glossary is intentionally small. It defines the minimum language needed to reason about elemental character, Artifact collapse, measured state, topology, traversal, crossings, and presentation. It does not add new gameplay ontology.

It extends `M0.7-MINIMAL-ARTIFACT-GRAMMAR.md` and must not reintroduce the speculative semantic fields removed by that reset.

## Element

One of the eight fixed positions in the elemental ring:

```text
Void → Fire → Chaos → Ground → Aether → Water → Order → Sky → Void
```

The ring is one shared cyclic relation system. Elements are not eight unrelated stat fields.

## Relation Wheel

The one canonical directed relation shape shared by all eight Elements.

When any Element is read as the local origin / `Is` seat, the other Elements are interpreted by relative clockwise/counter-clockwise offset:

```text
 0  Is
+1  Affinity
+2  Anchor
+3  Vice
 4  Nemesis
-3  Conflict
-2  Need
-1  Wants
```

For example, reading the wheel from `Fire` gives:

```text
Fire   = Is
Chaos  = Affinity
Ground = Anchor
Aether = Vice
Water  = Nemesis
Order  = Conflict
Sky    = Need
Void   = Wants
```

Reading from `Water` uses the same wheel rotated to Water:

```text
Water  = Is
Order  = Affinity
Sky    = Anchor
Void   = Vice
Fire   = Nemesis
Chaos  = Conflict
Ground = Need
Aether = Wants
```

Do not author one relation table per Element. The wheel is one function read from different origins.

## Elemental Identity

The weighted elemental composition that describes the Artifact's default elemental character.

Elemental Identity may contain one or more of the eight Elements with weights. It is not a single winning Element and it is not the Artifact's deterministic instance identity.

Examples:

```text
Fire 10
```

and:

```text
Fire  10
Water  1
```

are both valid Elemental Identities.

Each participating Element contributes its own rotated reading of the same Relation Wheel. Its Element weight scales that contribution.

Use **Elemental Identity** when ambiguity is possible. It answers "what elemental composition is this thing?" Instance identity answers "which realization is this?"

## Profile

The weighted overlay of Relation Wheel readings contributed by an Artifact's Elemental Identity.

Conceptually:

```text
for each participating Element E with weight w:
    rotate the canonical Relation Wheel to E
    scale that reading by w

overlay all contributions
    = default elemental Profile
```

For:

```text
Fire  = 10
Water = 1
```

the Profile preserves both readings:

```text
Fire    = Is×10       + Nemesis×1
Chaos   = Affinity×10 + Conflict×1
Ground  = Anchor×10   + Need×1
Aether  = Vice×10     + Wants×1
Water   = Nemesis×10  + Is×1
Order   = Conflict×10 + Affinity×1
Sky     = Need×10     + Anchor×1
Void    = Wants×10    + Vice×1
```

Fire therefore dominates the default character without deleting the Water contribution.

The overlay does not require normalization merely to exist. Exact normalization/scaling policy may be introduced only where a consuming rule needs it.

The Profile is the Artifact's **default mapping**. Properties, Relations, Clock/Hourglass context, other Artifacts, and admitted rules may vary how that default mapping participates in a particular resolution. The universal Relation Wheel itself does not change.

## Attribute

A weighted elemental relation available to interaction from an Artifact's Profile, including admitted local deltas or variations.

Attributes are the usable elemental character through which an Artifact participates in Clock, Hourglass, Grain, Artifact-to-Artifact, and other elemental interactions.

An Attribute is not an arbitrary root field such as age, mobility, moisture, race, material, or body plan.

A useful reading is:

```text
8 Elements
    ↓ weighted composition
Elemental Identity
    ↓ overlays rotated Relation Wheels
Profile
    ↓ local variation / participation
Attributes
```

## Property

An admitted rule or configuration that changes how an Artifact participates in resolution.

A Property may vary, constrain, gate, grant, transform, or interpret Attributes, Stats, Relations, Crossings, the default Profile, or other admitted behavior. It may be persistent or conditionally active.

Properties are not forced into a one-way hierarchy. A rule may read a Statline or measured State and activate a Property; that Property may then alter an Attribute or affect later resolution.

A Property may change the local/effective reading of an Artifact's default elemental mapping without redefining the canonical Relation Wheel.

## Stat / Statline

A **Stat** is a measured value. A **Statline** is an addressable collection or shape of measured values.

Stats are part of what can be measured about the current system. They are not required to be terminal outputs or scalar-only leaves.

Rules may read a Stat or Statline as evidence for later resolution. For example, a measured threshold may satisfy a condition that admits or activates a Property. The measurement does not itself mutate the world; an admitted rule interprets it.

## State

The measured record of what is true at a particular time/resolution point `T`.

State is evidence. State is not the rule that changes the world.

Conceptually:

```text
State(T)
  ↓ read by admitted rules / Relations / Properties
proposed effects / local mapping changes
  ↓ constraints + propagation + collapse
State(T+1)
```

State may record Elemental Identity, default/effective Profile readings, active Attributes, active Properties, Statline, Relations, Positions, Clock/Hourglass condition, and other resolved facts. This is not a frozen storage schema.

A statement such as "State changes the elemental mapping" is therefore shorthand for: a rule reads measured State, that condition admits a change to how the default mapping participates, resolution settles it, and the next State records the effective result.

The separation is:

```text
Relation Wheel      = universal relation law
Elemental Identity  = weighted elemental composition
Profile             = default weighted overlay
rules / Properties  = local deformation / interpretation
State(T)            = measured record of the current result
```

## Address

A stable referent within an addressable structure.

An Address need not be geometric. A Clock Tick, Hourglass side, Neck, POI, Zone boundary, threshold, Relation endpoint, or Artifact may be addressable.

## Position

Where an entity currently occupies an addressable structure.

Position is measured as part of State.

## Relation

An admitted typed and weighted connection between addressable things.

Relations may be derived from relative structure, points, boundaries, Zones, Attributes, State, constraints, and available resolution budget.

Keep the unresolved and admitted forms distinct:

```text
relative structure
      ↓ weighted / constrained possibility
Virtual<Relation>      candidate / unresolved connection
      ↓ admission
Relation               connection admitted by the current solve
      ↓ traversal weight / cost / character
weighted Relation
      ↓ optional deeper collapse
Artifact.Road          materialized addressable connection
```

The exact weighting can itself depend on Attributes and current State. A Relation does not need to become an Artifact merely to exist. Artifactization is one possible deeper resolution of the connection.

## Traversal

Actual movement through admitted topology from one addressable Position toward another.

Traversal is not teleportation. The entity moves through the structure connecting the old and new addressable positions unless a future explicit mechanic defines another traversal rule.

## Crossing

A witnessed passage during Traversal through a meaningful boundary into a newly addressable State or Position.

Examples native to the current design shape include:

```text
Clock Hand crosses Tick
Grain crosses Hourglass Neck
Persona crosses Zone boundary
measured value traverses and crosses a Threshold
```

A State delta must not masquerade as a Crossing. The relevant entity/value must actually traverse the admitted structure and pass the boundary.

A Crossing is a causal resolution point: rules, Properties, Relations, constraints, and propagation may react before the next State settles.

## Artifact

An addressable thing in the world/system.

An Artifact may remain unresolved, partially resolved, or realized. Artifact type describes what an Artifact may become; it does not imply a matching Card.

## Virtual

A valid unresolved or partially resolved possibility.

Virtual state is first-class. Lack of resolution budget does not make the possibility invalid.

## Instance

A sufficiently collapsed realization of a Virtual possibility at an addressable collapse position.

Instance identity is deterministic and includes collapse address where needed to distinguish repeated same-type siblings. This is separate from Elemental Identity.

## Collapse

Budgeted resolution that makes Virtual possibilities more specific while preserving unresolved frontier when budget or constraints stop further resolution.

Collapse may resolve type, topology, Elemental Identity weights, Tokens, Relations, composition, or other admitted state without requiring every dimension to settle at once.

## Budget

The explicit limit on how much resolution may occur.

Existing dimensions include:

```text
maxHops      → relation depth
maxSlots     → opened composition edges
maxInstances → Virtual → Instance materializations
```

Budget changes resolution depth, not authored meaning or validity.

## Card.Artifact

The active generator of Artifact possibilities.

```text
Card.Artifact
    ↓
Virtual<Artifact>
    ↓ weighted / constrained collapse
Artifact.<Type>
    ↓
Instance<Artifact.<Type>>
```

A type does not require a matching Card. There is no required `Card.Persona`, `Card.Item`, or `Card.Biome` symmetry.

## Pack

A composition of possibilities, Artifacts, and Relations used to author or constrain a local resolution context.

Pack is a composition mechanism, not a parallel runtime.

## Token

A weighted semantic candidate available during collapse.

Tokens may help resolve, refine, name, or configure an Artifact. A Token is not itself an Attribute, Property, Stat, or State.

Concrete Token vocabulary and eligibility remain deliberately open.

## Sprite

A generative visual projection of resolved Artifact State.

Sprite projection may select a base image, recolor/palette-shift it, replace parts, add overlays, vary pose/orientation, or otherwise adapt presentation from Artifact type, Elemental Identity, Profile/Attributes, Tokens, Properties, State, and presentation context.

Sprite output is downstream presentation. Visual projection must not silently become authoritative simulation State.

## Core invariants

1. **One elemental ring.** There are exactly eight shared elemental positions.
2. **One Relation Wheel.** Every Element uses the same canonical relative relation function from its own origin.
3. **Elemental Identity is weighted composition.** An Artifact may carry multiple Element contributions; no single winning Element is required.
4. **Profiles overlay contributions.** The default Profile is the weighted overlay of each participating Element's rotated Relation Wheel.
5. **Do not erase minority contributions.** `Fire 10 / Water 1` remains Fire-heavy and Water-present.
6. **Elemental Identity and instance identity are different.** One describes elemental composition; one uniquely identifies a realization.
7. **Attributes are weighted elemental character.** Do not use `Attribute` as a dumping ground for arbitrary semantic root fields.
8. **Properties change participation in resolution.** They may vary, constrain, gate, grant, transform, or interpret admitted behavior and the effective reading of the default Profile.
9. **Stats are measurements.** Rules may read them and later resolution may change them; they are not mutation authority by themselves.
10. **State is the measured record.** State says what is true at `T`; rules explain change toward `T+1`.
11. **Crossings require traversal.** Do not teleport between addressable states and call the delta a Crossing.
12. **Relations may remain derived.** `Virtual<Relation>` → admitted/weighted `Relation` → optional `Artifact.Road` are different resolution depths of compatible structure.
13. **Budget reduces resolution, not validity.** Unresolved frontier remains valid first-class state.
14. **Presentation is downstream.** Generative Sprite variation may reflect resolved State but cannot silently mutate it.
15. **Keep the why.** State should remain inspectable back through elemental contributions, Relations, Traversals, Crossings, Properties, measurements, constraints, and collapse decisions that produced it.

## Deliberately soft seams

These remain intentionally unresolved until implementation proves a stronger contract is needed:

- concrete Token vocabulary and Token Pack semantics;
- exact normalization/scaling policy when a consumer needs a scalar from an overlaid Profile;
- exact policy/threshold for Relation materialization into Artifacts such as Roads;
- complete Property / Statline / Attribute rule language;
- whether every traversable Relation needs an explicit intermediate path Address;
- detailed Sprite composition and fallback grammar;
- type-specific semantic content.

Do not fill these seams with speculative fields merely to make examples look complete.
