# M0.6-B — Dragon Golden Path

## Purpose

Prove the new generative model independently from the frozen M0.5 regression oracle.

Dragon is deliberately used because it exercises identity, elemental possibility, rarity, properties, derived stats, and unresolved component slots without requiring Pack/DAG behavior yet.

## Lifecycle

```text
Artifact/Persona Definition
  → Dragon Template
  → Dragon Reference
  → Dragon Virtual
  → Dragon Instance
```

## Required distinction

The upstream stages describe possibility; they do not pretend that a specific Dragon already exists.

- Definition declares dimensions such as element, rarity, properties, stats, and slots.
- Template fixes `species = Dragon` and declares priors/rules, but does not select an element, rarity, age, temperament, or exact stat.
- Reference binds the Dragon possibility to a boundary/context such as `Spire.guardian` inside Mountains.
- Virtual evaluates the context into weighted possibilities and stat ranges.
- Instance is the first stage with a selected element, rarity, property values, and exact stats.

## Current example

Mountains provide a contextual elemental field. The Dragon Virtual therefore weights Ground and Fire more strongly than unrelated elements while keeping all supported outcomes unresolved.

The same Dragon Template referenced from a Swamp produces a different elemental possibility field without changing the Template.

## Not yet in scope

- no general DAG propagation;
- no `SolveBudget` enforcement;
- no Pack realization;
- no Situation/POI materialization;
- no realized Hourglass object;
- no inventory collapse.

Those stay unresolved intentionally. Their slots are visible so later milestones can connect them without changing what Dragon means.

## Pass condition

- M0.5 exact regression remains green;
- Dragon follows all five stages;
- no selected element/rarity/exact stats exist before Instance;
- context changes the Virtual possibility field;
- same seed + same Virtual deterministically returns the same Instance.
