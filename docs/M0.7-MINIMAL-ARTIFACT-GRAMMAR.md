# M0.7 Minimal Artifact Grammar

Status: machine-verified implementation candidate; owner acceptance pending.

## Why this reset exists

The prior generative experiment prematurely invented semantic fields and named generator identities. That made the system look richer while actually narrowing what it could eventually express.

This slice resets the active generative model to a deliberately small grammar.

## Core invariant

> **Card.Artifact generates Artifacts. Artifact types describe what an Artifact may become. A type does not imply a matching Card.**

The active generator is:

```text
Card.Artifact
    ↓
Virtual<Artifact>
    ↓ weighted collapse
Artifact.<Type>
    ↓
Instance<Artifact.<Type>>
```

Examples of admitted types already evidenced by the repository include:

```text
Artifact.Persona
Artifact.Item
Artifact.Biome
Artifact.Clock
Artifact.Hourglass
Artifact.ClockFace
Artifact.ClockHand
Artifact.Hour
Artifact.HourglassLock
Artifact.HourglassFilter
```

There is no `Card.Persona`, `Card.Item`, or `Card.Biome` in this minimal model.

## Universal shape

The root Artifact grammar currently knows only:

```text
Elements      1..8
Attributes    0..N
Properties    0..N
Stats         0..N
```

`Attribute`, `Property`, and `Stat` were intentionally generic handles in this reset. Their clarified M0.7 meanings now live in `M0.7-CORE-GLOSSARY.md`; this document must not be read as permission to restore speculative semantic fields such as body plan, mobility, cognition, age, elevation, relief, moisture, material, durability, travel speed, or attack speed.

## Elemental composition

The existing eight-element vocabulary remains the only named universal elemental vocabulary:

```text
Void
Fire
Chaos
Ground
Aether
Water
Order
Sky
```

The follow-on glossary clarifies their intended semantics:

- the eight Elements occupy one cyclic ring;
- one canonical Relation Wheel defines relative roles around that ring;
- **Elemental Identity** is a weighted composition of one or more Elements;
- each participating Element contributes the same Relation Wheel rotated to that Element and scaled by its weight;
- the Artifact's default Profile is the overlay of those contributions;
- Attributes expose weighted elemental relations/deltas for interaction.

Therefore a composition such as:

```text
Fire  10
Water  1
```

must not be collapsed semantically into "Fire only." Fire contributes strongly and Water contributes weakly to the same overlaid Profile.

The generator's existing weighted elemental possibility should be read as the precursor to this weighted Elemental Identity, not as eight separately authored profile tables.

Exact normalization/scaling beyond preserving the weights belongs to consuming rules, not to the universal grammar.

## Existing relation base

The relation graph contains only topology already evidenced by current repository structures.

```text
Artifact.Persona       is-a      Artifact
Artifact.Item          is-a      Artifact
Artifact.Biome         is-a      Artifact
Artifact.Clock         is-a      Artifact
Artifact.Hourglass     is-a      Artifact
Artifact.ClockFace     is-a      Artifact
Artifact.ClockHand     is-a      Artifact
Artifact.Hour          is-a      Artifact
Artifact.HourglassLock is-a      Artifact
Artifact.HourglassFilter is-a    Artifact

Artifact.Clock
  contains → Artifact.ClockFace ×1
  contains → Artifact.ClockHand ×1..N
  contains → Artifact.Hour ×12

Artifact.Hourglass
  contains → Artifact.HourglassLock ×0..1
  contains → Artifact.HourglassFilter ×0..1
  bound-to → Artifact ×1

Artifact.Biome
  contains → Pack.Situation ×0..N
```

This graph deliberately records admitted topology rather than deriving new behavior.

## Relation-driven kind bag

`TokenPack.ArtifactKind` is derived from the relation graph rather than maintaining a second list of Artifact kinds.

Therefore adding a new admitted relation:

```text
Artifact.NewType is-a Artifact
```

makes that type available to Card.Artifact's kind possibility space without adding `Card.NewType` or changing the generator kernel.

Weights are currently neutral/equal placeholders. Real weighting rules belong to later work.

## Budgeted topological collapse

`collapseArtifactTopology()` applies the existing solve-budget dimensions to relation traversal:

```text
maxHops      → how far composition may recurse
maxSlots     → how many contains-edges may be opened
maxInstances → how many Virtual Artifacts may become Instances
```

A low budget does not invalidate the Artifact. It leaves a typed frontier.

### Clock proof

A forced `Artifact.Clock` has the admitted minimum topology:

```text
Clock
├ Face ×1
├ Hand ×1
└ Hour ×12
```

With full topology budget the same Card.Artifact invocation resolves the root plus all fourteen required children.

With `maxHops = 0`, only the Clock Instance resolves and all required child relations remain blocked by the hop frontier.

With `maxSlots = 2`, Face and Hand resolve while the twelve Hour relations remain blocked by the slot frontier.

With `maxInstances = 0`, the root remains a valid `Virtual<Artifact>`.

No Card or relation definition changes between those runs.

## Instance identity

Artifact **instance identity** includes the collapse address. Repeated same-type children such as twelve `Artifact.Hour` Instances therefore remain deterministic and unique.

This is distinct from **Elemental Identity** in `M0.7-CORE-GLOSSARY.md`:

```text
instance identity  → which realization is this?
Elemental Identity → what weighted elemental composition characterizes it?
```

Do not overload one meaning with the other in implementation or interface labels.

## Non-spawning relations

A relation does not automatically mean "spawn another object."

For example:

```text
Artifact.Hourglass bound-to Artifact
```

records an admitted reference/ownership relation. It does not cause Card.Artifact to manufacture a new owner.

Optional contains-relations (`0..1`, `0..N`) are likewise visible topology without forced materialization.

## Quality lines

> **Elements are universal; meaning is typed later.**

> **One Relation Wheel; weighted elemental compositions overlay it.**

> **Relations describe what may compose before semantics describe what that composition means.**

> **A type may exist without a Card. Card.Artifact is the generator.**

> **Budget changes resolution depth, not authored meaning.**

## Deliberately deferred

- type-specific semantic schemas;
- semantic Token vocabularies such as Dragon / Elf / Sword;
- exact profile normalization/scaling policies beyond preserving elemental weights;
- weighted relation selection beyond neutral admitted kinds;
- optional-relation selection policy;
- dynamic propagation through Clock / Hourglass relations;
- combat/action grammars;
- migration of frozen named M0.5/M0.6 fixtures into this minimal model;
- UI replacement.

The old named-content fixtures remain regression custody only. They are not the active generative grammar defined by this slice.
