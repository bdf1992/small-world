# M0.7 RC1 Revision — Tokens, Cards, Packs, Artifacts

Status: **owner correction in progress; RC1 remains REVISE**

RC1 exposed a structural authoring error: named world nouns were modeled as executable Card/Pack Templates.

That is not the intended Small World model.

## Correct primitive roles

```text
Card
  generates possibility

Pack
  composes possibility

Token
  names / classifies a resolved possibility

TokenPack
  supplies themed vocabulary + threshold rules

Artifact
  is the Virtual / Instance that actually exists
```

Named outcomes such as:

- Dragon
- Bandit
- Bear
- Mantis
- Sword
- Shield
- Staff
- Lantern
- Cave
- Ruin
- Spire
- Observatory
- Swamp
- Desert
- Mountains

are **Tokens**, not Cards or Packs.

They may appear as derived naming/classification over an Artifact once enough structural facts are available.

## Correct lifecycle

```text
structural Definition
        ↓
generic Card / Pack
        ↓
Reference
        ↓
Virtual
        ↓ threshold projection
provisional Tokens
        ↓ bounded resolution
Instance
        ↓ threshold projection
settled Tokens
        ↓
world label / classification
```

A Token never creates its Artifact.

## Generic generators

The corrected active generator identities are semantic handles such as:

```text
card.persona
card.item
card.biome
pack.situation
```

They resolve structural dimensions rather than fixed names.

Examples:

### Persona Card

```text
bodyPlan
size
mobility
covering
cognition
armament
age
temperament
element
rarity
```

A resolved structure such as:

```text
bodyPlan = quadruped
mobility = flying
covering = scales
size = large
rarity >= T3
```

may satisfy the `Dragon` Token threshold.

The Card did not contain `species = Dragon`.

### Item Card

```text
geometry
function
scale
material
element
rarity
```

`geometry=blade + function=strike` may earn `Sword`.

`geometry=vessel + function=light` may earn `Lantern`.

### Situation Pack

```text
origin
enclosure
verticality
depth
decay
purpose
element
rarity
```

plus typed composition slots such as:

```text
guardian requires Artifact/Persona × 1
treasure requires Artifact/Item × 1
```

`origin=constructed + verticality=high + purpose=observe` may earn `Observatory`.

The Pack itself remains `pack.situation`.

## Token

A Token is intentionally inert vocabulary:

```text
Token
  id
  text
  role
  tags
```

A Token does not contain runtime behavior.

Example:

```text
token.theme.dragon
text = Dragon
role = noun
```

## TokenPack

A TokenPack is a typed collection of Token candidates and threshold predicates.

Examples:

```text
tokens.theme.classic-fantasy.persona
tokens.theme.classic-fantasy.item
tokens.theme.classic-fantasy.situation
tokens.elemental.core.*
```

This is how designers author themed vocabularies without teaching the kernel those names.

A fantasy TokenPack may call one structural outcome `Dragon` while another TokenPack could name the same structural outcome differently.

## Elemental composition

Theme and elemental Token Packs may both classify the same Artifact.

Example:

```text
Artifact facts
  bodyPlan = quadruped
  mobility = flying
  covering = scales
  size = large
  element = Ground

Theme Token
  Dragon

Element Token
  Stone

Rendered name
  Stone Dragon
```

The rendered name is a projection over Tokens, not lifecycle identity.

## Virtual thresholds

Token matching is allowed before final realization when a Virtual has enough probability support.

Example:

```text
P(bodyPlan=quadruped) >= .50
P(mobility=flying) >= .50
P(covering=scales) >= .50
P(size=large) >= .35
```

may produce a provisional `Dragon` Token projection.

This is not final settlement.

An Instance earns the settled Token only from settled facts.

## Tuple graph relationship

Tokenization remains representable in the same tuple graph:

```text
(TokenPack, contains, Token)
(Token, accepts, Artifact/Persona)
(Token, threshold, PredicateSet)

(artifact#42, tokenized-as, token.theme.dragon)
(artifact#42, tokenized-as, token.element.stone)
```

`tokenized-as` is a derived/evidence relationship. It does not replace Artifact identity.

## Correction quality line

> **If adding a named world noun requires changing kernel/runtime code, the abstraction has failed.**

The correction proof introduces `Mantis`, `Lantern`, and `Observatory` as Token/content data only and requires the same generic Persona Card, Item Card, and Situation Pack to produce them.

The verification test also scans `src/kernel` and `src/runtime` to ensure those names do not appear there.

## Migration rule

The old named Templates (`persona.dragon`, `item.sword`, `pack.spire`, etc.) may remain temporarily only as frozen parity/regression fixtures while the live M0.7 authoring/world path is migrated.

They must not remain the active generative architecture.

A Token veneer over named Templates is not sufficient.

## RC status

RC1 remains **REVISE** until:

1. the active authoring session uses generic Cards/Packs;
2. Pack candidates point to generator Cards, not named outcomes;
3. world labels come from Token projections;
4. lineage distinguishes generator custody from Token naming evidence;
5. Authoring Document serializes generator + TokenPack authored truth without serializing realization;
6. the in-chat workbench demonstrates adding/reweighting Tokens and seeing generated outcomes change;
7. M0.5 whole-shape parity remains intact.
